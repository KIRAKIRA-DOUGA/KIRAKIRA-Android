## 组件、状态与副作用

- **标准组件优先**：使用 Material 3 Expressive 的组件，不用手绘控件替代已有标准组件，保持浅色、深色及系统强调色兼容。参考 [Compose Material 3](https://developer.android.com/develop/ui/compose/designsystems/material3)。
- **动效**：动画曲线统一取自 `MaterialTheme.motionScheme`。位移与形变使用空间动效（Spatial），透明度、颜色等有界属性使用效果动效（Effects）。侧栏（Rail）进出的位移与透明度共用无回弹的 `defaultEffectsSpec`。
- **单向数据流**：状态向下传递，事件通过回调向上传递。可复用组件只接收所需的状态和回调，不直接获取 ViewModel、Repository 或导航控制器。
- **参数顺序**：可复用 UI 的第一个可选参数是 `modifier: Modifier = Modifier`，作用于组件根节点；内容插槽放最后。见[参数示例](implementation/components.md#可复用-ui-参数示例)。
- **Modifier 工厂**：声明为 `fun Modifier.name(...): Modifier`，在接收者上追加修饰符并保留已有链；无效果的分支返回 `this`，不从空的 `Modifier` 重建整条链。函数用描述行为的 `camelCase` 命名，不加 `Modifier` 后缀，不通过抑制检查绕过接收者规范。参考[官方自定义 Modifier 指南](https://developer.android.com/develop/ui/compose/custom-modifiers)和[接入示例](implementation/components.md#modifier-工厂示例)。
- **状态归属**：按[状态提升原则](https://developer.android.com/develop/ui/compose/state-hoisting)选择所有者。局部临时状态用 `remember`，需要恢复的 UI 状态用 `rememberSaveable`，业务状态由 ViewModel 暴露只读状态；Flow 在屏幕入口通过 `collectAsStateWithLifecycle` 收集。
- **副作用**：组合执行体中不请求网络、写存储或执行导航。用户操作在事件回调中触发；与组合生命周期相关的工作使用 key 正确的 `LaunchedEffect`／`DisposableEffect`，并清理监听器。参见[副作用指南](https://developer.android.com/develop/ui/compose/side-effects)。
- **并发**：网络和磁盘工作不阻塞主线程；使用结构化并发，禁止 `GlobalScope`；捕获取消异常后必须继续传播。
- **设计值**：颜色、字体和形状取自 `KIRAKIRATheme` 与 `MaterialTheme`，不在业务页面散落品牌颜色。布局用 `dp`，字体用 `sp`。
- **列表与稳定性**：列表项使用稳定的业务 key。不为压制重组随意添加 `@Stable`／`@Immutable`。
- **预览**：可复用组件的 Preview 使用空表单、游客账号或空列表；需要展示特定状态时使用预览专用的虚构值，不依赖真实服务或运行中的 ViewModel。

## 按钮、单选框与阴影

阴影分两类。彩色表面的投影取实际容器色（选中的单选框取选中色），中性色表面的投影用黑色；这是“KIRAKIRA 彩色阴影”。栏面等原生投影由平台绘制。两类阴影都不提供开关，也不保存阴影偏好。

### 按压轮廓

按压形变按可见轮廓和场景选择，与阴影分别管理。“平面”指无阴影，“固定轮廓”指形状在按压期间不变。

| 场景 | 按压轮廓 |
| --- | --- |
| 实心、浅色、描边和平面文字按钮，包括确认、重试、复制、危险操作和顶栏保存 | 静止为圆角矩形，按住时变为药丸形 |
| 独立的实心、浅色及描边图标按钮 | 固定圆形 |
| 裸图标按钮，包括返回、关闭及输入框辅助操作 | 固定圆形，保留官方涟漪 |
| 关注按钮、独立选择按钮和颜色选择块 | 未选中时为圆角矩形，按住时变为药丸形或圆形，松开后恢复当前选择状态的轮廓 |
| 视频赞踩／收藏／分享／更多操作条、裁剪底栏的旋转图标 | 固定轮廓，保留选中状态反馈；裁剪“完成”按独立实心按钮处理 |
| `Segmented` 分段选择 | 空选时按下即显示滑块并跟手，已有选择时沿用底栏的按压与拖动动效 |
| FAB、播放器控制、图片／资料页叠层工具按钮、资料编辑页头像按钮、评论／弹幕发送按钮、账号侧滑删除按钮 | 固定轮廓 |

- 按上表判断，不按页面自行开启或关闭形变，不增加动画开关。
- 禁用或加载期间不触发形变。
- 按压只改变轮廓，不额外缩放或位移，不改变布局尺寸和触摸区域；表面、投影与装饰裁剪共用当前轮廓和同一个交互源。
- 关注、选择及播放状态自身的图标或形状动效不受固定轮廓影响。

共享参数与例外的接入见[按钮按压轮廓](implementation/components.md#按钮按压轮廓)。

### 投影

| 组件 | 静止 | 悬停／聚焦 | 按压 | 禁用 |
| --- | --- | --- | --- | --- |
| 普通实心按钮 | 2dp | 4dp | 8dp | 无阴影 |
| FAB | 6dp | 8dp | 12dp | 无阴影 |
| 单选框（仅选中且可用时） | 1dp | 2dp | 4dp | 无阴影 |
| 评论／弹幕输入框与发送按钮 | 4dp | 4dp | 4dp | 4dp |
| 设置页顶部特色卡片 | 2dp | 2dp | 2dp | — |

动态阴影按下用时 120ms，恢复或取消用时 180ms。

| 双层投影强度 | 彩色：环境层／主层 | 中性色：环境层／主层 |
| --- | --- | --- |
| 实心按钮、FAB 与卡片 | 25%／50% | 黑色 7.5%／15% |
| 单选框 | 12.5%／25% | 黑色 3.75%／7.5% |

强度不随交互状态变化，并乘以容器（或选中颜色）的透明度。

- **实心按钮**统一使用 `ShadowButtons` 中的共享封装，它保留了官方的填充、浅色填充、实心图标按钮与 FAB。不叠加原生投影或外层投影。文字、描边与裸图标按钮保持平面。实现见[按钮动态阴影](implementation/theme.md#按钮动态阴影)。
- **单选框**统一使用 `ShadowRadioButton`。投影只画在可见圆圈外侧，不改变官方布局、触摸目标与选中动画。整行处理点击时，行与单选框共用同一个交互源，单选框的 `onClick` 为 `null`。实现见[单选框动态阴影](implementation/theme.md#单选框动态阴影)。
- **设置页顶部特色卡片**（关于页页头、安全状态横幅、二步验证已启用卡片）使用 `MaterialTheme.shapes.large` 和共享的 `cardColorShadow`。阴影不随卡片内部控件的交互改变；待核对状态的横幅使用中性色。主题明暗与个性色卡片保留官方交互阴影。实现见[彩色卡片阴影](implementation/theme.md#彩色卡片阴影)。
- **评论／弹幕输入框与发送按钮**固定 4dp。输入框、禁用的发送按钮和中性色的可用发送按钮使用系统原生 elevation；彩色的可用发送按钮使用共享双层投影。发送按钮禁用时使用不透明的灰色容器与图标。
- **应用栏、刷新指示器**的阴影固定开启。`AccountFlowScaffold` 的认证与账号安全流程顶栏是例外：正文位于顶部时无阴影，滚离顶部后显示，仅由页面滚动状态驱动。见[栏面阴影](implementation/theme.md#栏面阴影)。

### 各类按钮

- **尺寸**：指定 Expressive 按钮尺寸时使用 `ButtonDefaults` 的官方尺寸常量（如 `MediumContainerHeight`），并把同一尺寸传给 `contentPaddingFor`、`textStyleFor`；有图标时同步使用 `iconSizeFor` 和 `iconSpacingFor`。需要按压形变时使用同尺寸的 `pressToRoundButtonShapes`。不得手写标准尺寸的高度、圆角、内边距或字号，也不得只放大容器而保留默认小字号。最小高度用 `heightIn(min = …)`，让内容能随字体缩放增高。
- **FAB**：表达“添加”的悬浮按钮使用 `ShadowFloatingActionButton`，默认圆形、`primary` 背景。只显示 Cerasus `add` 加号，不使用带文字的扩展 FAB；保留本地化的无障碍描述和操作期间的禁用语义。
- **分段选择**：带滑动指示块的横向单选组使用共享 `Segmented`，选择状态由调用方提供，可为空选。见[分段选择](implementation/components.md#分段选择)。
- **关注按钮**：个人主页与视频页统一使用 `FollowButton`。未关注时为 `primary` 实底并带投影；已关注时为灰色容器，不绘制投影。关注状态仍由原有业务流程拥有。
- **危险操作**：全应用使用主题错误色。实心按钮用 `ShadowButton(destructive = true)`，文字按钮用 `DestructiveTextButton`，菜单项用 `SegmentedMenuItem.destructive`。登出、移除账号、清除本机账号、关闭或解绑验证方式、舍弃未保存内容及隐私重置的确认操作都适用；取消和普通重试保留默认样式。页面只判断操作语义，不另配危险颜色。见[危险操作](implementation/components.md#危险操作)。

以下场景直接使用官方按钮，不接入共享阴影：

| 场景 | 做法 |
| --- | --- |
| 播放器黑底控制按钮 | 官方 `FilledIconButton`／`IconButton`／`TextButton`，不接入背景模糊；倍速入口在非默认值时使用主题强调色 |
| 资料页 Tab 未吸顶时的顶部按钮 | `BackdropButtons`：黑色遮罩加背景模糊，无阴影；吸顶后恢复普通图标按钮。见[黑底毛玻璃按钮](implementation/components.md#黑底毛玻璃按钮) |
| 视频详情操作条 | 官方 `ToggleButton` 与 `TextButton`，上方图标、下方计数或标签，固定圆形轮廓、无阴影；选中的赞踩使用 `primary` 前景与同色淡底纹。见[视频简介](implementation/content.md#视频简介) |

## 列表、开关与弹层

### 列表与分组

- **单组用普通列表**：只有一个内容组时使用普通 `Column`／`LazyColumn` 和官方 `ListItem`，不使用连接形状、`ConnectedListGroup`、`ConnectedLazyColumn` 或整组阴影。无分类的搜索结果属于单组列表。
- **多组才用连接列表**：存在多个语义分组时才使用连接列表，不为使用连接样式人为拆组。
  - 分组内的条目使用官方 `SegmentedListItem` 和共享的 `connectedListItemShapes(index, count)`。
  - 普通 `Column` 分组复用 `ConnectedListGroup`；多组列表中的独立条目在调用处显式包裹成单项分组。
  - 懒列表使用 `ConnectedLazyColumn`，通过 `connectedItemsIndexed` 声明稳定的分组标识和逐项内容，整组阴影由宿主统一绘制，条目不添加行级投影。可能增长的数据列表保留逐项懒加载、稳定 key、contentType 与分页。
- 不以整组 `Surface` 模拟列表项。静态占位使用无 `onClick` 的重载；无副标题时不传 `supportingContent`，不提供空内容 lambda。
- **分组标题**只在区分类别、说明操作范围或补充必要上下文时使用；与页面标题、条目名称重复且无其他作用时省略，并同时移除它的间距。无标题时省略 `title` 参数，不传空字符串，也不另加 `showTitle` 一类开关。
- **列表区域的辅助标题与数量摘要**统一使用 `titleSmall` 和 `onSurfaceVariant`，适用于最近搜索标题、搜索结果数量、评论总数、弹幕总数、标签页视频数量和屏蔽规则总数。数量摘要用“数字在前、单位在后”的本地化格式（如“3 条规则”“3 rules”），英文通过复数资源区分单复数，不使用“规则 · 3”这类中点分隔格式。历史日期标题、设置分类标题、主页与邀请码统计、赞踩数量保留各自的层级。邀请码统计是顶部表面里不加底板的三栏（未使用、总量、已使用），以竖分隔线隔开，标签 `labelLarge` 在上、数字 `headlineLarge` 在下；“未使用”一栏整体用 `primary`，其余标签用 `onSurfaceVariant`。生成入口是 FAB。
- **列表图标**：设置列表的前后图标使用裸露的 24dp 图标，继承列表内容颜色；危险操作使用主题错误色。花形等 MaterialShapes 图标容器只用于随状态切换形状的表达（如隐私可见性、邀请码使用状态）和独立的大图标展示。

### 开关

- 普通开关只通过 Switch 表达开启状态，整行背景和形状不随状态变化。整行点击切换，并提供 `Role.Switch` 与 `toggleableState` 语义；尾部 Switch 的 `onCheckedChange` 为 `null`。
- 只有功能总开关（如“显示弹幕”）使用 `checked` 重载保留整行强调样式。

### 菜单、对话框与弹层

- **下拉菜单**统一使用 `MenuPopup`，选项组之间用 `MenuDivider`。条目使用官方 `SelectableDropdownMenuItem` 和共享的 `menuItemShapes()`。见[弹出菜单](implementation/components.md#弹出菜单)。
- **单项选择用菜单还是底部 Sheet**取决于选择的语义，不按页面统一：
  - 表单里只改草稿的字段（如资料页的性别），选项是少量短文本、不需要图标或说明时，用锚定在该行的 `MenuPopup`，选中项尾部显示对勾。
  - 选择后立即提交（写服务端或设置），选项需要图标或说明，或多个入口共用同一个选择器、需要标题说明当前对象时（如隐私可见性），用 `ModalBottomSheet`，选项为连接列表，尾部用 `ShadowRadioButton`。
- **对话框**复用 `ActionDialog`：标题居中，图标是可选插槽。操作按钮按可用宽度自适应排列——一行放得下时横向靠右、主操作在末端，否则纵向全宽、主操作在前；不按操作数量或业务场景固定排列。主操作用 `ShadowButton`，次操作用平面文字按钮，关闭或取消放最后。日期选择器保留官方结构。见[普通对话框](implementation/components.md#普通对话框)。
- **危险确认弹窗**通过 `DestructiveActionIcon` 让顶部图标与确认按钮共用主题 `error` 色。
- **弹层背景**按内容决定：对话框、底部 Sheet、日期选择和开源组件详情中，包含连接列表条目时使用灰色（业务 Sheet 为 `surfaceContainerLow`），否则使用 `surface`。空列表、首次加载与错误占位使用 `surface`；刷新时已有条目则保持灰色。调用处按实际内容直接选择颜色，不探测组件树。见[弹层背景](implementation/theme.md#弹层背景)。

## 账号表单与保存

共享组件的接入见[账号流程布局](implementation/components.md#账号流程布局)。

### 保存方式

- **资料编辑**在顶栏右侧使用平面 `TextButton` 保存，不使用底部保存栏或 FAB。无修改和图片准备期间禁用；保存时保留标签并显示底边进度条。服务端已保存但同步失败时，按钮变为“重试同步”，只完成剩余步骤。离开时对未保存的修改做返回确认。
- **隐私设置**在单项选择或“全部设为”后立即提交，不另设“应用”按钮。
  - 请求期间禁用重复操作；明确失败时恢复最近确认的值并提示。
  - 结果不确定或写后核对失败时暂停编辑，重读核对后才恢复操作。
  - 提交完成前阻止返回，以免取消写请求。
  - 顶栏的重置图标需要确认，已是默认值时禁用。
- 两页保留设置页的 640dp 内容宽度上限和 16dp 留白，底部系统 Insets 随内容滚动，Snackbar 交给 Scaffold 管理。头像裁剪保留底部的旋转与完成操作栏。

接入见[设置表单操作区](implementation/account-settings.md#设置表单操作区)。

### 流程布局

认证、修改邮箱／密码和全部二步验证页面共用 `AccountFlowScaffold`：滚动表单加固定在底部的通栏主按钮，背景为 `surface`。

| 项目 | 取值 |
| --- | --- |
| 最大内容宽度 | 480dp |
| 横向页面留白 | 24dp |
| 标题 | 居中的主题色流程图标，半粗 `headlineLarge` |
| 标题到步骤进度 | 12dp，进度条高 4dp |
| 页头到表单、独立分组之间 | 32dp |
| 字段之间、登录表单到“忘记密码／注册”入口 | 24dp |
| 分组页头到字段 | 16dp |
| 分组标题到邮箱等上下文 | 4dp |
| 底栏顶部留白 | 16dp |

- 步骤进度向读屏完整读出当前步骤和总数；没有分步的页面不占位。
- 普通表单靠标题、对齐和留白分组，不加卡片底板。
- 验证步骤直接展示邮箱，不重复显示“账号”“电子邮件地址”“当前邮箱”这类标签；保留“身份验证”“新邮箱”等区分任务的标题。
- 只保留必要的后果、限制、状态和错误提示；没有提示时不预留间距。
- 主操作放在底栏的 `AccountFlowActionBar` 中，宽度与正文对齐。关闭或解绑使用危险操作样式。发送验证码、复制、打开验证器等辅助操作留在对应内容旁边；靠边的文字按钮复用 `FormTextButton`，让标签与正文边缘对齐。
- 二步验证管理页未开启时先单选验证方式再点“继续”，默认不预选；已开启时显示当前方式和底部的关闭／解绑按钮。安全首页保留设置页布局。
- 宿主统一处理键盘避让，底栏负责系统安全区域，Snackbar 避让底栏和键盘。

返回保护和敏感材料的处理见[分步输入与系统凭据](implementation/auth.md#分步输入与系统凭据)。

### 字段、错误与验证码

- 普通输入框复用 `FilledTextField`；密码输入复用 `PasswordTextField`，显隐状态只存流程内存，提交或页面失活后恢复遮蔽。
- 字段错误在输入框尾部显示 24dp 的 Cerasus `error` 图标（主题 `error` 色），说明使用官方 supporting text。错误图标只是装饰：不可点击，不单独提供无障碍描述。
- 全局错误使用错误色文字并向无障碍播报。错误和页面级反馈的出现与消失使用主题的快速过渡，移除后不留空占位。
- 六位验证码复用 `OtpInputField`。视觉上是六个独立的格子，底层只有一个编辑器，因此粘贴、退格、选择替换和 IME 操作都可用；不自动提交。邮箱验证码与普通 TOTP 为六位数字，允许备用码的输入同时接受数字和大写字母；TOTP 登录保留 24 位恢复码的完整输入入口。
- 验证码和恢复码只存流程内存，选择位置不使用可保存状态。
- 二步验证的状态横幅与已启用卡片：已启用用主题成功绿色，未启用用主题警告色，待核对用中性色。
- 二维码、设置密钥与一次性代码使用专用的浅色展示区；“打开验证器”和“复制”使用官方描边按钮，在所属区域末端对齐。

代码分组、换行与复制值的处理见[安全与二步验证](implementation/account-settings.md#安全与二步验证)。

## 图标与用户名

- 界面图标优先复用 Cerasus 中用途对应的资源，命名为 `ic_icon_<name>`，按需导入为 VectorDrawable。本地适配的图标命名为 `ic_custom_<name>`，保持相近的视觉重量、圆角和光学对齐；缺少同用途资源时可沿用已有的 `ic_symbol_<name>`。来源与许可见 [Cerasus 记录](../third_party/cerasus-icons/README.md#常用操作与箭头)和 [Material Symbols 保留资源](../third_party/material-symbols/README.md#保留的界面图标)。
- 底栏“首页”与“我”在选中、未选中及动画期间都保留 Cerasus 的实心轮廓。
- 错误状态的图标统一使用 `MaterialTheme.colorScheme.error`，包括页面、列表和媒体中的错误占位，以及错误对话框、卡片和字段校验。对话框、卡片和字段可复用 `ErrorIcon`。
- 独立展示用户名时统一使用 `@username`、等宽字体和 `onSurfaceVariant`，字号沿用所在组件的排版层级。用户名为空白时不显示该行。`@` 只在展示层添加，输入框、存储及 API 参数保留原始用户名；昵称回退使用用户名时沿用名称样式。

## 文案、本地化与无障碍

- **资源化**：界面文案放入字符串资源，包括错误、导航标题和无障碍描述；使用格式化资源和 plurals，不拼接可翻译的句子。
- **四种语言同步**：支持英语、简体中文、繁体中文（台湾用语）与日语。新增可翻译的 key 必须同时补齐四套文案，术语优先与 Cerasus 的多语言资源一致；品牌名标记 `translatable="false"`。

  | 语言 | 资源目录 |
  | --- | --- |
  | 英语（完整回退） | `res/values/` |
  | 简体中文 | `res/values-zh/` |
  | 繁体中文 | `res/values-b+zh+Hant/` |
  | 日语 | `res/values-ja/` |

  界面跟随系统语言，Android 13+ 通过 `res/xml/locales_config.xml` 声明应用语言；新增语言时同步该配置，并检查长文案和字体缩放。
- **标点**遵循 [Material 3 UX 写作指南](https://m3.material.io/foundations/content-design/style-guide/grammar-and-punctuation)：
  - 按钮、标签、导航项、菜单项、Tooltip、单行状态、短错误提示和空状态等单句文案不加句末标点。
  - 多句说明保留句号；问句用问号；进行中的状态用省略号，但按钮和菜单项不加省略号。
  - 中文和日语使用全角标点，英文使用英文标点。
  - 感叹号只在确有语气或品牌意图时使用；关于页的 `Alpha!` 是特意保留的例外。
- **不解释机制**：除非用户明确要求，界面中不添加解释功能如何运作的说明文字。保留必要的操作标签、状态反馈、错误信息和无障碍提示。
- **命名**：分类名称使用简短、具体的名词（如“用户”“内容”）；“管理”“规则”“更多”只在有实际含义时使用。开启流程已经表达了启用任务时，省略重复的“未启用”提示；概览中的当前状态，以及失败、待核对和结果不确定的提示必须保留。
- **不内置演示内容**：应用中不内置 Demo 账号、评论、弹幕、视频或邀请码。组件库里既有的开发者示例正文可以沿用中文，但它的入口、标题、操作和无障碍文案仍要同步各语言。
- **无障碍与适配**：交互控件提供语义和可读标签，纯装饰图标使用空描述；保证触摸目标、字体缩放和 TalkBack 可用。布局兼顾浅色、深色、窄屏和宽屏，使用 `start`／`end` 方向和系统 Insets，不按固定屏幕尺寸布局。

## 加载与刷新

- **四种状态**：异步页面明确表达加载、成功、空内容与失败；重试入口与操作语义一致。
- **读取失败保留已确认内容**：同一账号、同一查询的读取失败，保留已确认的内容（包括空结果）并给出失败反馈。网络、超时、限流、响应异常和未区分原因的业务拒绝都不是清空的依据；只有会话失效或服务端明确确认内容不可访问时才撤下旧内容。更换账号、查询或资源标识时不复用旧结果。
- **分页与写请求**：分页失败保留已加载的条目和分页位置，在对应区域手动重试。失败或取消后不自动重放写请求。
- **错误反馈的载体**：
  - 瞬时错误用 `Snackbar`，不使用 `Toast`。操作可能在页面关闭后才完成时，由导航宿主持有 Snackbar 状态并显示结果；系统画中画内不显示。
  - 页面级加载失败和需要点击重试的内容错误用 `ContentUnavailableView`。
  - 字段校验保留输入框的错误状态和 supporting text。
- **首次加载与刷新要区分**：已有内容刷新时保留内容与布局，不在列表顶部插入占位的加载指示器。已加载的空结果也算已有状态，刷新时保留空状态。下拉刷新统一由 `ContentPullToRefresh` 的覆盖式指示器反馈，不与列表内的加载指示器同时出现。调用 `ContentStatus` 时检查传入的 `loading`，不要把刷新状态直接映射为列表内加载状态。
- **圆形加载器**：页面、列表、媒体与条目内的不确定进度复用 `IndeterminateCircularProgressIndicator`。它封装的是官方 Material 2 的圆形加载器——这是 Material 3 Expressive 界面中有意保留的例外，不使用 Expressive 形变加载器。默认颜色为主题 `primary`，媒体区域为白色。

  | 场景 | 直径／线宽 |
  | --- | --- |
  | 页面、图片、分页及播放器中央缓冲 | 40dp／4dp |
  | 圆形图标按钮、账号行、列表尾部操作、小窗播放控件 | 24dp／2dp |
  | 下拉刷新内部（40dp 白色圆形容器） | 20dp／2.5dp |

- **按钮加载反馈**：带文字的操作按钮在可见表面底边显示 4dp 的横向不确定进度条，保留原有文案和图标；圆形图标按钮在图标位置显示居中的圆形加载器。两类按钮加载时保持正常配色和触摸区域，阻止重复操作，并向读屏提供操作名称和进度状态。共用忙碌状态的多个按钮只在实际执行操作的那个上显示进度。见[按钮加载反馈](implementation/components.md#按钮加载反馈)。
- **下拉刷新**保留官方手势，拉动和刷新两个阶段的图形按 Material 2 的 swipe-to-refresh 表现。有可量化进度的其他加载可以使用确定进度指示器。
- **骨架**：资料页首次读取关注／粉丝数时，用静态圆角骨架占住数字位置，并向读屏保留加载状态。

## 毛玻璃应用栏

- **范围**：普通顶部栏（含认证、设置、历史、标签和头像裁剪页面）、主界面底部的胶囊导航栏和视频页的 Tab 栏固定开启毛玻璃，不提供开关。视频画面与播放控件、图片查看器和系统导航栏不在此范围。
- **接入**：普通页面使用 `FrostedScaffold`，由它管理采样状态和顶部背景。页面不重复添加顶栏阴影。
- **栏面绘制**：背景复用 `ThemeShadows.barSurfaceLayer`。半透明背景的 alpha、形状与 elevation 必须设置在同一个背景图层中，前景的文字、图标和指示器独立绘制、不随背景变淡。不对整栏设置 alpha，不使用阴影蒙版、差集裁剪或按系统版本特判阴影。
- **系统版本**：Android 12+ 使用 Haze 背景采样；Android 8.1–11 使用 90% 不透明度的栏面，不采样、不模糊。不使用原生 backdrop，也不启用它的全局实验开关，原因见[实现说明](implementation/components.md#毛玻璃应用栏)。
- **样式**：模糊使用主题 `surface`、20dp 模糊半径和 80% 不透明度的底色遮罩，不加噪点或折射。
- **顶栏配色**：导航与操作图标使用 `onSurfaceVariant`，标题使用 `primary`。品牌 Logo 与流程标题图标保留强调色，媒体顶栏保留白色控件。
- **认证流程**：认证与安全操作页的返回使用平面的官方 `IconButton`；认证的所有步骤都不提供关闭按钮，根登录页通过系统返回退出。
- **共用顶部表面的页面**：资料页的封面、资料区与 Tab，视频页的播放器占位区域与 Tab，各自属于同一个顶部表面，由它的背景承载 elevation；Tab 不独立投影，表面内部的交界处不产生阴影。
- **Insets**：顶部安全区域放入滚动内容，刷新指示器通过 `indicatorTopPadding` 保持在栏下。Tab 栏的实测高度放入列表顶部的 `contentPadding`，刷新指示器、评论分页工具栏和输入面板同步避让。

各场景的阴影承载方式见[栏面阴影](implementation/theme.md#栏面阴影)。

## 固定页面顶栏

带标题和返回入口的普通二级页面使用 `PageTopAppBar`。顶栏固定在页面顶部，不随正文滚动；搜索、认证流程和媒体等场景保留各自的布局。

- 顶栏只接收解析后的标题与事件；内容、滚动状态和 Snackbar 仍归页面。
- 顶部与底部的系统内边距必须随内容滚动：`Column` 把内边距放在 `verticalScroll()` 之后，`LazyColumn` 使用 `contentPadding`。不要在滚动容器外应用完整的 `innerPadding`，那会截短底部的 edge-to-edge 区域；同时消费 Insets，避免重复避让，确保末项能滚到导航栏上方。
- 内容较短的页面也让滚动容器占满可用高度，使空白区域能接收下拉手势。

接入示例见[实现说明](implementation/components.md#固定页面顶栏)。

## 主题配色约束

- **只有一套配色方案**：所有颜色使用 Material Design 2 风格的经典强调色与中性表面，默认是项目粉色，不提供配色算法选择。主题、色板与选色器统一通过 `rememberSeedColorScheme` 生成完整的语义颜色，不能只替换 `primary`。
- **系统强调色**是主题色板中的一个选项，默认关闭，仅在 Android 12+ 显示。选择它不会覆盖手动或自定义的色值。
- **直接引用角色**：主色文字、选中标签与指示线直接引用 `MaterialTheme.colorScheme.primary`，不逐组件计算对比度或调整明度。`onPrimary` 在主题生成阶段按“白色优先”决定：白色与原色的对比度达到 2.5:1 时用白色，否则用黑色。这个取舍接受极浅或极深选色时前景对比不足，也不保证按钮文字达到 4.5:1。
- **栏面**：底色浅色为纯白、深色为深灰，关闭色调高度叠加，避免栏面被重新染色。
- **控件底色**：普通输入框、验证码格、主搜索与标签选择器的输入区域、设置与历史收起的搜索栏、`Segmented` 轨道和 Chip 的普通态共用 `ThemeColorDefaults.controlContainerColor`，按紧贴的背景取色：

  | 控件所在的背景 | 底色 |
  | --- | --- |
  | 纯白（如浅色主题的白色资料卡片） | `surfaceContainerLow` |
  | 浅灰或深灰（如灰色隐私页面、播放设置弹层） | `surfaceContainerHigh` |

  默认以主题 `surface` 为父背景；控件直接放在其他底色上时，传入实际颜色。
- **输入框**：普通输入框复用 `FilledTextField`，默认配色、圆角、内阴影和错误过渡由组件提供，不在调用处重复配置。验证码格、主搜索、标签选择器和收起的搜索栏复用同一套底色与内阴影。评论／弹幕编辑器使用自己的容器配色与阴影。
- **Chip**：官方 `FilterChip`、`InputChip`、`AssistChip` 和 `SuggestionChip` 使用无描边的 `CircleShape`。普通态文字为 `onSurface`、图标为 `onSurfaceVariant`；可用且选中时为 `primary` 实底与 `onPrimary` 前景。`FilterChip` 和 `InputChip` 通过 `AppChipDefaults` 取配色，另外两种直接使用各自的官方配色 API。
- **共享入口**：`ThemeColorDefaults` 提供栏面颜色、普通页面背景、设置页面背景和控件底色。对比度与 HCT 工具是主题生成器的私有实现，不对外使用。
- **自定义颜色**：草稿只在确认后保存，取消不改变主题。自定义色值与当前生效的色值分开存储，并保存“预设／自定义”的选择状态，不能只凭色值相等判断选中项。

配色生成、颜色保存与选色组件的实现见[主题实现](implementation/theme.md#主题实现)。
